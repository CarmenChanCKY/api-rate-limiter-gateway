# Plan: Scalar API Documentation Setup

## Goal

Set up Scalar API documentation at `http://localhost:3000/api-docs` that documents the Target API endpoints from `docker/target-api/server.js`. Users can browse docs without auth, but requests tested through Scalar require the API key.

## Architecture

```
Client
  ↓
GET /api-docs ──→ Gateway (:3000)
                    ↓
              Scalar UI + OpenAPI spec
              (generated by swagger-jsdoc
               from docker/target-api/server.js)
```

## Files to Change

### 1. Install dependencies (package.json)

```bash
npm install swagger-jsdoc @scalar/express-api-reference
npm install -D @types/swagger-jsdoc
```

- `swagger-jsdoc` — generates OpenAPI 3.0 spec from JSDoc comments in route files
- `@scalar/express-api-reference` — Express middleware that serves the Scalar API reference UI
- `@types/swagger-jsdoc` — TypeScript types for swagger-jsdoc

### 2. Create `src/config/swagger.ts`

swagger-jsdoc configuration:

- **Base OpenAPI spec** (definition):
  - `info.title`: "Target API"
  - `info.version`: "1.0.0"`
  - `info.description`: Getting started guide (get API key → enter in auth → test endpoints)
  - `components.securitySchemes.bearerAuth`: HTTP Bearer scheme (`type: "http"`, `scheme: "bearer"`, `bearerFormat: "API Key"`)
  - `security: [{ bearerAuth: [] }]` — global security requirement so all endpoints require auth
  - `tags`: `["Getting Started", "Health", "Users"]` — ordered so `Getting Started` (contains `/get-api`) renders at the top of Scalar

- **Scan path** (apis): `["./docker/target-api/server.js", <gateway-api-file>]` where `<gateway-api-file>` is chosen at runtime by file-existence detection:

  ```ts
  import { existsSync } from "node:fs";

  // Read the compiled file in the production Docker image (dist/), or the TS
  // source in local dev (src/). Both carry the @swagger JSDoc comment blocks.
  const gatewayApiFile = existsSync("./src/app.ts")
    ? "./src/app.ts"
    : "./dist/app.js";

  apis: ["./docker/target-api/server.js", gatewayApiFile],
  ```

  - `docker/target-api/server.js` — scanned at runtime (works in local dev + Docker via volume mount)
  - `gatewayApiFile` — resolves to `./src/app.ts` when present (local dev / repo-root CWD), else `./dist/app.js` (production Docker image `/app` CWD)
  - Paths/swagger-jsdoc scans resolve relative to the process CWD
  - `/** @swagger */` blocks survive tsc compilation because `tsconfig.json` has no `removeComments`, so `dist/app.js` carries the same JSDoc as `src/app.ts`

### 3. Modify `src/app.ts`

Add two new routes **before** the `app.all("/{*path}", ...)` catch-all proxy route:

```ts
import swaggerJsdoc from "swagger-jsdoc";
import { apiReference } from "@scalar/express-api-reference";
import { swaggerOptions } from "./config/swagger.js";

const spec = swaggerJsdoc(swaggerOptions);

// Serve raw OpenAPI spec JSON
app.get("/api-docs.json", (_req, res) => res.json(spec));

// Serve Scalar UI
app.get("/api-docs", apiReference({
  content: spec,
  layout: "classic",
  hideSearch: true,
  agent: { disabled: true },
  mcp: { disabled: true },
  authentication: {
    preferredSecurityScheme: "bearerAuth",
  },
}));
```

**Placement**: These routes must come AFTER `/get-api` and BEFORE `app.all("/{*path}", ...)`.

Add a `/** @swagger */` block above the existing `/get-api` route in `src/app.ts`:

```js
/**
 * @swagger
 * /get-api:
 *   get:
 *     tags: [Getting Started]
 *     summary: Get the API key
 *     description: Returns the current runtime API key. No authentication required.
 *     responses:
 *       200:
 *         description: The API key for authenticated requests
 */
app.get("/get-api", ...);
```

- `/get-api` stays OUTSIDE `verifyAPIKeys` (no auth, matches CONTEXT.md)
- The `Getting Started` tag first in the `tags` array places it at the top of Scalar (layout/config controls display order; source order in `app.ts` is already first anyway)

### 4. Modify `docker/target-api/server.js`

Add `/** @swagger */` JSDoc comments to each route:

- `GET /` — status message
- `GET /api/users` — get sample user
- `GET /api/users/:id` — get user by ID (with path parameter)
- `POST /api/users` — create user (with request body)

Minimal annotations with: `tags`, `summary`, `parameters` (for `:id`), `responses`.

### 5. Modify `docker-compose.yml`

Mount only the Target API source (needed for `docker/target-api/server.js`):

```yaml
gateway:
  volumes:
    - ./docker/target-api:/app/docker/target-api:ro
```

Read-only mount — Gateway cannot modify Target API source. No `src` mount is needed: the Gateway's `/get-api` docs come from `dist/app.js`, which is already in the production Docker image.

### 6. No changes to

- `Dockerfile` — volume mount handles file access
- `tsconfig.json` — swagger-jsdoc reads files at runtime, not compile time
- `docker/target-api/Dockerfile` — no changes needed

## Request Flow

```
1. GET /api-docs → Scalar UI loads (no auth needed)
2. GET /get-api → Returns API key
3. User pastes key into Scalar's Bearer token field
4. User clicks "Send" on an endpoint
   → GET /api/users with Authorization: Bearer <key>
   → verifyAPIKeys middleware validates
   → Forwarded to Target API
```

## When Adding New Routes

For Target API routes, add a JSDoc comment above the route in `docker/target-api/server.js`:

```js
/**
 * @swagger
 * /api/new-endpoint:
 *   post:
 *     tags: [Something]
 *     summary: Does something
 *     responses:
 *       200:
 *         description: Success
 */
app.post("/api/new-endpoint", (req, res) => { ... });
```

For Gateway routes (e.g. `/get-api`), add the JSDoc comment in `src/app.ts` directly; it is picked up at runtime from `./src/app.ts` (dev) or `./dist/app.js` (Docker) via the file-existence detection in the `apis` scan list.

The spec regenerates automatically on the next request to `/api-docs.json`.

## Scalar UI Configuration

The `/api-docs` route passes the following config to Scalar:

| Setting | Value | Purpose |
|---------|-------|---------|
| `content` | `spec` | The generated OpenAPI document (uses `content`, NOT `spec` — Scalar expects `content` at the top level) |
| `layout` | `"classic"` | Use the classic Scalar layout instead of modern |
| `hideSearch` | `true` | Hide the sidebar search bar |
| `agent` | `{ disabled: true }` | Hide the "Ask AI" chat button (enabled by default on localhost) |
| `mcp` | `{ disabled: true }` | Hide the "Generate MCP" button |
| `authentication.preferredSecurityScheme` | `"bearerAuth"` | Pre-select the Bearer auth scheme |

The `/api-docs` UI cannot force users to get an API key before testing. Instead:
- The OpenAPI `info.description` guides users: get key → enter in auth → test
- Missing/invalid key returns a 401 from the `verifyAPIKeys` middleware (the real enforcement)

## User Decisions

- **Doc generation**: swagger-jsdoc (JSDoc comments required per route)
- **Gateway source reading**: file-existence detection (`existsSync` on `./src/app.ts`) — read TS source in dev, compiled `dist/app.js` in the Docker image. No `src` volume mount needed, no `NODE_ENV` plumbing.
- **Route location**: inline in `src/app.ts` (simple, no separate file)
- **JSDoc detail level**: minimal (basic descriptions, params, response codes)
- **Auth guidance**: OpenAPI `info.description` instructs users to get the API key from `/get-api` first (Scalar UI cannot force/block this)
- **UI customization**: hide AI chat (`agent.disabled`), hide Generate MCP (`mcp.disabled`), classic layout, hide search bar
- **Document /get-api**: Gateway route documented via JSDoc in `src/app.ts` (added to the `apis` scan list), tagged `Getting Started` and placed first in the `tags` array so it renders at the top of Scalar

## Implementation Notes / Gotchas

- Scalar expects the OpenAPI document under `content`, not `spec` — using `spec` causes "Document not found in configList" and a blank skeleton page
- `/api-docs` is NOT behind auth (matches the CONTEXT.md diagram), but the requests tested through it are (via `verifyAPIKeys` on the catch-all proxy route)
- The production Docker image ships only `dist/`, not `src/`. To avoid mounting `src`, the swagger config uses file-existence detection (`existsSync("./src/app.ts")`) to read `./src/app.ts` in dev or `./dist/app.js` in Docker. The `/** @swagger */` comment survives compilation (no `removeComments` in tsconfig), so `/get-api` shows in both environments.
- Paths are CWD-relative. Dev runs `tsx` from the repo root (so `./src/app.ts` resolves); Docker runs `node dist/server.js` from `/app` (so `./dist/app.js` resolves).
